# 原生 PDF JSON 数据传递优化

依据 [函数级诊断](2026-11-01-native-pdf-bottleneck-diagnosis.md)，调整原生事实收集、文档几何、表格候选、页面容器和行内文字准备的内部数据传递。

- 内部已有 JSON 树的对象字段使用私有 `value_object!`，通过 Value 的直接转换和复制组成对象，不再经过通用 Serialize/NumberValueEmitter 重建。任意 Serialize 类型和 JSON 字面量仍使用原 json 宏。
- 已拥有的行数组、规则数组、准备结果和页面大字段直接移交；不再 json 序列化后丢弃原树。
- 保持原候选、仲裁、分类、几何、异常与预算行为，保留 `arbitrary_precision` 和 `float_roundtrip`，没有按输入名称或内容绕过算法。

## 实测

相同 129 页输入、相同公开 API 原生规则参数、64 页窗口。每个版本在独立进程连续调用两次；无 cProfile/调用栈采样，保留两边相同的轻量阶段记录。

| 调用 | 修改前秒 | 修改后秒 | 总耗时下降 | 原生分析前/后秒 |
| --- | ---: | ---: | ---: | ---: |
| 首次 | 38.201 | 29.772 | 22.1% | 26.949 / 18.996 |
| 复用 | 38.202 | 31.069 | 18.7% | 26.891 / 19.905 |

原始结果：`build/value-transfer-{before,after}-20261101.json`。两次 Markdown 哈希均与修改前一致。此为一份原生规则工作负载、每版本两次调用，不是交替多轮基准；不外推到所有 PDF、模型扫描流程或峰值内存。本场景依然慢于之前约 12.55 秒的 Python 结果，未完成追平目标。
