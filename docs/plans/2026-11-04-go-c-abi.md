# Go preview and shared C ABI v1

## Implemented boundary

`bindings/c` is a thin Rust adapter to the existing seven-format SDK. It exports
ABI version, one operation dispatcher and a response release function. Numeric
engine handles are registry-validated; calls retain an engine lease, reject
same-engine reentry/concurrency and catch Rust panics at the boundary. Responses
own metadata plus separate binary image/drawing buffers, avoiding Base64 and
repeated asset JSON serialization. Callers release every response once.

`bindings/go` uses **cgo on both Windows and Linux**, with the same callback and
response conversion. Its small C loader selects LoadLibraryExW on Windows and
dlopen on Linux. No Windows-only Go syscall callback implementation is retained.
The module has no third-party Go dependencies. It carries an identical copy of
the canonical C header so installing the module does not depend on sibling source
directories.

Go exposes path/bytes/reader/list parsing, options, warmup, loaded roles, native
errors, progress callbacks, result writing and idempotent close. Responses are
copied into independent Go-owned data before native release. Callback errors
return unchanged; callback panics are caught on entry and re-raised only after
the native call has returned, so they do not unwind across C frames. Explicit
close is recommended; a finalizer is a fallback. Global ORT/module ownership
continues for the process lifetime. No parsing/model algorithms were rewritten.

## Build and distribution

Portable w64devkit GCC was downloaded from its official release into
`build/tools/w64devkit`, verifying the upstream asset digest; provenance is saved
in `build/tools/w64devkit-source.json`. System installation and global PATH were
not changed. Go 1.27.3 was already installed locally. The source module declares
Go 1.20 minimum; minimum-version compilation itself has not been verified.

`build_go_sdk.py` produces a deployable directory and ZIP with the C engine,
ORT, private Windows CRT, isolated PDFium, GEOS, headers, notices and a file hash
manifest. CUDA builds add the matching ORT providers and existing custom operator
library. Runtime paths/model discovery continue to use shared Rust resources.
This is a source/local preview, with explicit native DLL/SO path; no public Go
module tags, native-download service or release artifacts have been published.

## Validation

- Two Rust C ABI unit tests passed: x64 layouts, invalid buffers, response free,
  create/close, repeated close and stale handles.
- Go acceptance passed all seven existing format references (Markdown, middle
  JSON, content list and image hashes), stream input, independent results after
  close, callback cancellation/reentry/panic, concurrent separate engines,
  unknown configuration rejection and output path traversal rejection.
- CPU detector/recognizer warmup and two scanned/mixed PDFs matched the previous
  Java/Python output baseline.
- `go test -race ./...` and `go vet ./...` passed on Windows with cgo.
- A separate Go consumer module used a local `replace`, built an executable,
  then ran against the extracted ZIP runtime with PATH restricted to System32
  and no Python/Go/compiler environment. Seven formats and PDF drawing output
  passed. The executable directly imports only KERNEL32.dll and msvcrt.dll.
- The ZIP payload's 29 file hashes and canonical/distributed header equality
  were checked. Linux C loader syntax was checked using WSL Ubuntu GCC.

Evidence: `build/go-sdk-consumer/receipt.json`, output/logs beside it, source
tests in `bindings/go`, native build archives under `build/go-sdk`.

Linux Go/native package execution, actual CUDA inference, provider/custom-op CRT
coexistence, full accuracy/performance/peak-memory benchmarks, signing and public
module/native artifact releases remain outside this local CPU acceptance.

## Consistent default progress view

Go's default parse view now matches Java's stage labels, 20-cell progress bar,
native `processing` time, lifecycle messages, stdout/stderr split, duplicate
counter suppression and batch reset. Interactive streams use carriage-return
updates; redirected streams use throttled lines. `ProgressMode` / the
`RAPIDDOC_PROGRESS_MODE` environment variable can force bar/plain output.
Custom callbacks replace the default parse view; download lifecycle/size logs
remain visible. `ProgressLogging` can disable the parse view. These are host
presentation changes, with no Rust parsing or native-runtime rebuild.

Removed the temporary formatter from the standalone demo at
`D:/CodeProjects/GoProjects/rapid-doc-go-demo` and the SDK CLI. Both pass nil to
use the binding default. Eight Go test functions passed with race checks; vet
also passed. The demo was run on the user's 14-page thesis-template PDF with the
real model pipeline: six expected prediction/assembly labels were present,
table completion occurred once, and Markdown, middle JSON and content-list JSON
matched the user's prior run exactly. Evidence is in
`build/go-progress-check/receipt.json` and separate stdout/stderr captures.
