# 表格三层证据评分开发方案

状态为独立 Python 版已实现并完成第二轮择优优化。等用户用实际 PDF 确认效果后，再同步 Rust。

32 页、42 张难例表的同裁图回放中，原规则选中较高分或同分的表为 26 张，三层证据首版与原规则组合为 29 张，第二版组合为 31 张，平均 TEDS 分别为 62.63、64.33、64.79。禁用旧结构择优并保留文本与合法性保护时，三层证据在强制双跑下选中 22 张，平均 TEDS 58.05。两版组合均调用备用 39 次，原规则调用 34 次。第二版强制双跑的选择一致。

另从六个文件名前缀分层随机抽取 12 页，按表框 IoU 一对一匹配了 18 张表。新旧输出选择一致，平均 TEDS 均为 91.05，均有 16 张选到两候选中的较高分或同分结果。TATR 调用由 9 次增至 10 次，第二版重跑新增一次推理耗时约 0.26 秒。留出集样本较少。

第二版分方向累计框线证据。候选增加行或列时，分别核对对应方向的框线和空带。原图框线与实际 OCR 归属同时支持切换时，允许纠正旧算法基于框重叠近似归属作出的否决。关键数值保护仍然生效。

第三轮在 TATR 解码时修复内部缺列。先用多行重复且对齐的高置信数值提出候选列，再核对新增列实际恢复的 OCR 实例和原有文字保留情况。42 张难例的同裁图回放中，平均 TEDS 从 64.79 升至 65.58，较优或同分结果从 31 张增至 32 张。调用仍为 39 次。18 张留出表的候选 HTML、选择和调用均一致。末尾缺行和合并格比较仍待处理。

第四轮固定两份候选 HTML，只调整择优。行列规模相同时，对覆盖明显不同的原图线段单独评分，并结合实际 OCR 归属和整表间距校验。对多处分散空行，要求备用保留文字并改善 OCR 归属，同时维持原图线段和间距表现。42 张难例中，TATR 调用仍为 39 次，采用由 27 张增至 29 张，较优或同分由 32 张增至 34 张，平均 TEDS 由 65.58 升至 65.99。18 张留出表的选择一致。

首版保留旧触发及择优逻辑，同时允许三层证据触发备用或在改善明确时切换。新增行需要独立的分隔证据，避免把同一视觉行的对齐改善误判成应该增加逻辑行。若备用丢失主候选保留的高置信独立数值，继续保留主候选。原生线坐标不能可靠映射时使用裁图检测的线段。

## 目标与现状

用同一套原图证据解决两个问题。先评估主候选是否有足够明显的缺陷，决定是否运行备用模型。备用候选生成后，用同一份证据比较两套网格，输出更可靠的 HTML。部署仍支持按需回退，开发评测先双跑以隔离择优效果。

当前主模型为 UNET + SLANet，常用备用模型为 Table Transformer（TATR）。Python 已有基于文字保留率、OCR 框间隔、局部错行和连续空行的回退，以及 TATR 漏行修复。新方案要把已有几何线索整合到候选边界的比较中。

原 20 页有 24 张检测到的表，最近一次逐表对照有 18 张选中两候选中的较高分或同分结果。后续 12 页的 18 张表中有 8 张选到较高分或同分候选，其余 10 张包括 4 张未触发 TATR、6 张已运行但未选到较高分候选。这两批是开发与回归样本。泛化效果以独立留出集为准。

## 输入与坐标

- 每张表只构建一次原图证据。输入是表格裁图、共享 OCR 四点框及置信度、可用的原生 PDF 表线和表格方向变换。公式、勾选框和图片提示沿用现有数据流，作为独立类型保留。
- 两个候选各自提供 HTML、单元格框、逻辑行列范围和合并关系。优先沿用模型在匹配阶段记录的 OCR token ID 与单元格归属。缺少真实归属时，可用框重叠近似估计并降低置信度。重复金额按 OCR 实例比较。
- 裁图、OCR 框、原生线段和候选框使用同一裁图像素坐标。明确处理页面缩放、裁图偏移、90°/270° 旋转以及模型预处理缩放。几何无法对齐时，该层记为不可用。
- 调试时可画出 OCR 框、原图线段、间距证据和候选边界。正式评分直接比较坐标、区间与文字归属，避免浏览器重排 HTML 改变列宽。

## 三层证据

| 证据层 | 提取和比较方式 |
| --- | --- |
| 文字 | 核对高置信 OCR 实例是否被保留、是否在合适的单元格里，以及候选边界是否穿过有字区域。分别记录普通文本、独立数值和符号的遗漏。允许一个单元格容纳多条视觉行。 |
| 框线 | 优先取 PDF 矢量线，扫描页使用裁图检测的横竖线。清理短噪声和文字笔画，再按方向、位置容差和重叠区间比较。部分线段仅支持其覆盖的区间。 |
| 间距 | 从原始 OCR 框独立推断反复出现的列间空带，以及多个列共同支持的行间空带。记录有效支持行数、列数、分隔范围和冲突。连续多行文本只在跨列分隔证据充分时视为新增数据行。 |

有线表优先使用有足够覆盖的线段。无线表更多依赖重复的间距和 OCR 归属。半框表按区段组合证据，例如表头有横线的部分使用框线，表体缺竖线的部分使用对齐和空带。未检测到线只表示框线层证据不足。底色变化可在后续作为辅助证据验证。

### 参考实现

- DocVortex 优先复用矢量线裁切、方向归并和局部分隔线覆盖度。入口见 [规则表线段](../../rapid_doc/model/table/rule_table.py#L82) 和 [分隔线覆盖度](../../rapid_doc/_vendor/docvortex_core/analyzers/native/pdf/_table_recovery/vector.py#L823)。
- img2table 参考栅格横竖线提取、无线表文本对齐与空白区域分析。仓库已有 [适配层](../../rapid_doc/model/table/img2table_backend.py)。候选评分独立实现，img2table 推出的完整网格可以作为额外候选参与评测。
- 候选边界按覆盖区段比较。长边可分段匹配，保留合并单元格中有依据的局部断开。候选分隔穿字或与稳定空带冲突时才形成明确负证据。

## 决策流程

1. **主候选评估。** 记录文字缺失、无效网格、漏掉的可信边界、切穿文字的边界。缺陷明显时运行备用模型。缺少某层证据时，只用可用层判断。
2. **候选质量保护。** 文字完整性和 HTML 网格有效性分别计算。网格异常时仍保留文字统计。存在可靠坐标证据时，可先修复局部网格再复验。备用结果丢失主结果保留的独立金额等关键值时，拒绝该次切换。
3. **同证据择优。** 对每套网格独立记录有支持的边界、被漏掉的可信边界、被切穿的 OCR 框、错归与漏归的文字。对齐两个候选的边界区段，统计恢复和破坏了哪些证据，避免靠多画边界提高分数。按证据置信度及可用区段归一化，记录各层贡献与有效证据量。分差不足或证据相互冲突时，保留主候选。
4. **收敛旧规则。** 评测阶段同时记录旧规则和新评分的决策。通过留出集后，将可由新评分表达的错行、漏列、空行和串格检查并入统一判断。保留少量独立保护，包括关键值、网格合法性和低置信度时保留主结果。退役哪些规则以对照结果为准。

首版重点是候选比较。阈值、权重和是否需要额外校准由数据决定。运行时使用原图与 OCR 证据，评测标注只用于离线比较。

## 开发步骤

1. **贯通候选与证据输入。** 检查 [表格流水线](../../rapid_doc/backend/pipeline/analyze_utils.py#L479) 的裁图、原生线段和方向变换，在 [候选生成](../../rapid_doc/model/table/rapid_table.py#L312) 补充实际文字归属。保留公开的 HTML 返回格式。验证相同数字分别归格、带合并格的逻辑索引、方向变换和原生线段坐标。
2. **实现证据提取和边界比较。** 在 [回退质量模块](../../rapid_doc/model/table/fallback.py) 附近实现共享证据。先加文字归属与间距，再加局部表线。算法核心在代码中写中文注释，说明坐标系、证据何时可靠、缺失时如何处理、为何触发或切换。
3. **接入离线回放。** 同一裁图和 OCR 跑主模型、TATR，保存候选、各层证据、原始决策和耗时。修改比较算法时复用这些数据。额外保存页内表框或稳定的表格 ID，便于将同页多表逐一对应。对照文字、文字加间距、三层证据和旧方案。
4. **接入按需触发。** 在 [模型回退入口](../../rapid_doc/model/table/rapid_table.py#L164) 分别记录未触发、运行后保留主候选、采用备用候选、规则引擎提前返回。日志给出证据量、分数差和拒绝理由。对比全双跑上限、按需回退漏判及新增开销。
5. **验证后同步。** Python 先跑下列测试和两批难例，再在独立留出集验收。用户确认实际 PDF 输出后，将通过验收的证据与决策同步到 Rust，并用相同回放数据做跨语言对照。

## Rust 同步记录（2026-11-14）

已将当前 Python 的表格回退与候选择优同步到 Rust：

- `rust/rapiddoc/src/pipeline/table_evidence.rs` 提取共享 OCR、栅格线、原生矢量线与间距证据。记录真实 OCR 实例归属，原候选网格与裁掉噪声边缘后的输出网格分开保留。
- `table_fallback.rs` 同步结构证据、重复数值匹配、空行、错行和内容完整性检查。无效 HTML 仍统计已有内容，最后一行漏写结束标签时保留该行证据。
- `tables.rs` 同步触发条件与候选比较，独立保留新证据的 3% 文字保留门槛、旧网格的条件性 5% 门槛，以及数字实例不得丢失的保护。UNET、SLANet、TATR 都传递真实文字归属，SLANet 过滤 OCR 后仍关联原实例编号。
- TATR 后处理同步缺行恢复、经多行独立数值确认的缺列恢复、合并格去重和合并范围更新。新列必须恢复先前漏归的数值，并保留旧候选已有的 OCR 实例。
- Python Rust 绑定增加回退日志，区分未调用、调用后保留主模型、采用备用模型，并输出证据差与数字保护结果。

核心算法注释写在 Rust 代码里。运行时不读取样例文件名或 OmniDocBench 标注。TATR 网络输入尺寸和推理精度没有降低。
