## 范围与固定条件

7 份本地原始 PDF 共 54 页：small_ocr（8）、示例1-论文模板（14）、49－长表格-密集型（1）、demo1（13）、比亚迪财报（9）、示例7-研究报告（5）、含印章（4）；另加此前固定的 129 页混合语料，共 183 页。所有文件完整解析。

运行包固定为 sdk-memory-owned-final，原模型取自既有 Python 兼容位置，不使用旧优化图磁盘缓存。Python 和 Rust 使用同一 ORT 1.23.0 环境、CUDA 设备 0、auto、公式/表格开启、原默认参数及 pdf_pages_batch=64；请求配置和公开默认值逐项比较。原 Python 的 RapidOCR 默认还会加载未使用的方向分类器，该辅助模型也在清单中冻结，Rust 不创建这个未使用的会话。

冻结 953 个模型、代码、配置、SDK 和验收文件的路径/大小/SHA256，测试结束再次检查；7 份服务器 PDF 与本地 SHA256 一致。每份文件分别启动隔离进程，Python/Rust 顺序执行并交替先后顺序，每端同一引擎调用 3 次：一次首次调用、两次复用调用，复用结果取中位数。首次调用包含惰性模型加载；验证输出和序列化耗时不计入解析时间。

内存/显存由父进程每约 50 ms 采样目标解析 PID，避免工作进程 GIL 影响；显存不计其他业务服务。工作进程在验证输出前发出结束标记，父进程据此停止采样，避免快照/图片比较抬高峰值。另记每次调用前释放上一结果、GC 并静置 1 秒后的 RSS/显存，以及调用后保留结果静置 1 秒后的状态。原始采样与检查点均保留。三次调用只能观察短期趋势，不能证明无限次调用没有内存增长。

输出比较包括规范化后的完整 middle_json/content_list/Markdown 和图片像素/SVG 内容，以及 Markdown 原始字节；图片文件编码差异使用既有像素规范化规则，不是原始编码字节一致声明。不修改精度阈值。

## demo1 差异的版本根因

服务器原 Python 环境的 pdftext 是 0.6.3；Rust 原生文字分组按 0.7.1 移植。第 5 页读取到的 3,178 个字符及其完整字典逐项一致，原 Python 将它们分为 78 行，Rust 为 455 行。0.6.3 将两条竖排文字合并成长行，填充到较小检测框时不满足整行覆盖率门槛，8 个长竖框被移除；0.7.1/Rust 分行后可以填入。Python 填充前后输入已捕获，说明不是 OCR 模型少检出：before 中存在这些框，after 才移除。

本地现有 pdftext 0.7.1 与 Rust 对同一页的原生 blocks 逐字段一致，均为 455 行。服务器使用相同 PDFium 库的再次诊断也证明字符字典完全一致，排除了字符读取/模型压缩导致的文字丢失。图片内容一致；变化集中在第 5 页两段文字及后续行编号、文字范围，其他 12 页的 middle_json 相同。Rust Markdown 比服务器 Python 多 92 个字符。

这是原 Python 依赖版本与移植基准的行为差异。当前 pyproject 允许 pdftext >=0.6.2,<0.8.0，因此仍是需要明确处理的兼容边界；此轮没有为了逐字相同删掉 Rust 文字，也没有改业务 `.venv`。尚未对齐依赖后再做整套 Python CUDA 复测，不把本地原生分组检查称为对齐版本后的整篇模型验收。
