## 已确认可单独验证

- **整页 MD5 按需计算**：Python `rapid_doc/backend/pipeline/model_json_to_middle_json.py` 当前每页执行 `bytes_md5(page_pil_img.tobytes())`，包括无图片资产的页面。可在首次裁图/表内填图需要命名时计算、同页复用，保持命名种子、写入顺序、图片像素及错误行为。Rust 实现/36 组对照见 `2026-11-01-native-reference-and-hash.md`、`scripts/migration/accept_asset_hash_cache.py`。Python 有自己的像素取值和哈希实现，收益必须用 Python 实测，不套用 Rust 的秒数。
- **已优化模型、模型运行配置与前后处理**：对话此前已有模型优化实验；后续按各实验文档和脚本逐项核对 Python 是否已使用。保持原模型、优化模型、失败/精度不符的候选严格区分；同一 ONNX 图的收益可能跨语言复用，但需验证模型路径、精度、输入/输出、会话参数、批次和加载缓存，不能声称全都自动适用。

模型实验入口：[模型优化归档索引](model-optimization-index.md)，包括公式 M 的投影外提/注意力融合/FP16 存储候选及版面 V2/V3 的已测结果。按该索引核对实际模型哈希、配置与精度边界，不把未采用的 INT8/V3 压缩方案当成可默认启用的优化。

## 需要重新测量后决定

- 推理会话/模型复用、批次组织、重复图像编码解码、裁图/几何中间数据和 PDF 句柄是否已经复用。先分析 Python 实际调用次数及分配，发现重复才改；没有足够收益就不增加复杂度。
- 对确实重复的通用处理做内部复用，保持异常顺序、页面批次边界和所有解析规则；不能按特定文档打补丁。

已有否定证据：[2026-10-30 Python 复用收益验证](2026-10-30-python-reuse-and-rust-performance-next.md)。当时 64 页目录中行准备/聚类/变换合计仅约 0.115 秒，deepcopy（含初始化）约 0.142 秒，已有绘图摘要和基线缓存；据此未新增 Python 缓存。后续没有新的热点证据时，不重复添加这些缓存，也不把带 cProfile 的耗时与无追踪运行比较。

## 不应直接照搬

- Rust 的 RGB→RGBA→RGB 冗余是迁移引入的；Python 默认 `page_to_image → bitmap.to_pil().copy()` 没有该往返。Python 仍有必要的模式整理/复制，不据 Rust 收益虚构 Python 有同一问题。
- Rust 的 Value 深复制/再序列化、所有权移交和借用改造不能机械照搬；Python 多处本来就传对象引用。
- 无收益/不符合精度要求的 PNG 滤波、模型压缩或量化候选，不纳入默认方案。不得为加速取消任意精度整数、浮点兼容或识别规则。
