# 原生 PDF 只读表格页与文字行准备

用户要求：继续 Rust 提速且保持精度，后续也优化 Python，并记录此前可共享的优化。Python 待办与已知不适用/收益不足的方案已集中到 [Python 性能后续工作](python-performance-followup.md)，不同时改动当前 Python 对照。

## 依据与改动

对上一最终安装版 `native-reference-r2-20261101` 重新采样：原生分析仍约占主线程样本 79%；Value serializer 和 JSON 子树 clone 分别约 27.7%/28.2%，彼此重叠，不能相加。原始栈/汇总在 `build/native-reference-r2-stack-20261101.tsv`、`build/native-reference-r2-stack-summary-20261101.json`。优化链接会合并符号，不把无意义的“覆盖率函数出现在全部栈”等叶节点名称当作实际热点。

- `closed_rule_pipeline::Page` 的只读行改为 `Cow<Value>`；正常候选、画线准备、页面策略和浅色表头借用原页行。只读遍历统一取得 `&Value`，不再复制携带完整 chars 的行树。
- 需要跨多类补充候选复用的缓存，显式转换成自有行，不保存悬垂引用；原有限预算分支的准备和 charge 次数保留。
- `prepare_source` 直接接收源页与小型选项；角度循环、续表匹配、规则候选和页面策略不再为只读准备构造完整 source JSON 副本。所有候选、排除、顺序、标题/续表和仲裁规则继续执行。
- `source_lines::prepare_owned` 接收已有行的所有权，按原 marker/default/未知字段覆盖顺序构建行；输出行/画线/局部行数组直接移交。公开借用入口和原错误检查仍保留。
- 原生事实收集直接移交局部行/画线和字符几何 pairs，避免先序列化再复制刚生成的数组；表格候选提交后的选定行与矢量公式请求也不再做重复的 Value 再序列化。

没有改变模型、阈值、数值精度或公开 API。保留 `arbitrary_precision`、`float_roundtrip` 及有兼容精度用途的 `wire` 转换。
