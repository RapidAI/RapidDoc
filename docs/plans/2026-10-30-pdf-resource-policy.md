# PDF 正式入口的容量策略修复

状态：额外预算及UNET重叠兼容问题已修复，最终包已安装到项目原`.venv`并验证。只处理本轮容量问题，没有调整模型、识别参数或解析算法来回避难文档。

## 原因

`demo2.pdf` 的“公式累计预处理工作量超过预算”来自迁移时额外加入的2.56亿估算操作量阈值。它累计多个公式批次的工作量，不是当前内存占用，也不是模型或原Python的限制；分批处理仍会被累计拒绝，因此不能仅靠扩大数值修复。

扫描还发现裁图数量、累计像素、JSON节点/字节、表格网格、候选和文本修复等额外门槛。正式入口现在采用共享的Python兼容资源作用域，默认不启用这些人工门槛；开发诊断入口与调用方明确指定的资源预算独立保留。

## 处理范围

| 类别 | 额外门槛示例 | 正式入口处理 |
|---|---|---|
| 公式预处理 | 累计2.56亿操作、3200万累计张量/像素 | 取消默认累计预算，保留溢出检查 |
| 公式/Unicode文本 | 64KB、固定修复工作量与迭代次数 | 按原规则修复至收敛，不截断文本 |
| OCR/版面裁图 | 1000个区域、3200万累计像素、识别宽度4096 | 不限制完整文档的区域数量或累计像素，不改排序、批次共同padding和缩放规则 |
| 模型张量 | 默认1600万/3200万元素 | 默认采用容器可表示范围；显式会话容量仍生效 |
| PDF输入 | 默认256MiB、10000页、字符/对象/路径数量 | 正式入口不设置这些额外默认值；文字API的可选限额默认None |
| 页面/全文JSON | 固定字节、节点、候选成员、工作量 | 默认不限制；显式HostResources仍生效 |
| 表格 | 候选、格子、逻辑行列、HTML/文字数量 | 移除默认人工门槛，保留实际索引、跨度及形状校验 |
| 配置 | 公式batch不超过64、线程不超过64 | batch只要求正整数，线程按运行库int32可表示范围校验 |

兼容作用域位于`rapiddoc-core::resources`，由共享Rust正式入口启用，线程内嵌套、退出和异常展开均恢复原状态；不依赖Python实现算法，后续语言绑定使用同一引擎即可继承。JSON/工作量显式限额仍通过`RAPIDDOC_RESOURCE_LIMITS`或Rust的`HostResources`配置；不设置时没有额外默认预算。低层诊断调用仍可使用其原有有限预算。

保留的是无效尺寸、非有限数、整数/长度乘法溢出、真实张量形状、模型输入约定、运行库错误等检查。原Python已有的规则也保留，例如分类采样页数、OCR候选筛选、UNET的1024缩放、PDF Form的15层采集，以及原图背景证据的400万/1600万像素规则。这些不能与额外的全文容量门槛混为一谈。

## 原Python兼容修复

公式预算移除后，文档进入后续表格阶段，暴露`UNET 逻辑格重复覆盖`。原Python的`_build_table_grid()`使用后写覆盖，不因模型产生重叠格而拒绝整篇。共享Rust `wired::legacy_html()`现在严格保留这个归属顺序；独立安全预览`wired::html()`仍拒绝重叠。没有跳过表格、吞异常或按文件名分支。
