# 检测内存输入及表格重复拷贝优化

范围：通用实现优化，不按文件名、表格文字、页号或内容特征增加生产分支；保留原算法、模型、阈值、分组、batch、padding、遮罩和异常策略。

## 已确认的额外工作

1. 表格样式准备在每个单元格调用 `cell_side_map` 前，对整页 tight_bboxes 执行 `.cloned()`，再筛取该格所需条目。改为借用原映射，缺字段仍传原来的空对象；输出及工作预算不变。
2. 正式正文检测把补白、遮罩后的 RGB 编码成 PNG，随后模型入口立即解码。正式路径新增拥有像素的输入，RGB→BGR在原缓冲区交换通道，复用同一检测前后处理；公开 PNG 适配器保持兼容。检测任务 ID、顺序、target shape、crop_source 不变，识别仍使用原始未遮罩来源。
3. 检测来源改为借用 PNG 字节，避免整批源字节复制。单页内存像素沿用每图及累计32M像素预算，累计原始 RGB 最大约96MB，推理后释放；不宣称峰值内存降低，正式峰值比较仍待。
4. 添加正文检测输入准备、检测执行、识别裁图，以及原生表格守卫、几何、恢复、提示、文字和模型阶段计时。细分项是父阶段的组成部分，不应与父阶段重复相加。

Python OCR 进度条的25/22项是分辨率分组数，Rust日志66/118项是检测图像数，不能据此认定Rust重复执行了更多次模型。原Python默认检测batch也是1，本轮未改变检测batch。

## 基线与验证方法

旧包同一密集表格原语输入，三次中位数：恢复加渲染1.940468秒，单独渲染1.265568秒；接口计时包含JSON解析和返回转换。输入和期望输出保存在 `build/dense-table-overhead-20261029/`，仅作基准负载，不进入生产代码。

验证依次进行：75组原检测输入像素及新旧通路张量完全相同；受影响的表格恢复/渲染、实际CPU检测及表格OCR；两个独立常驻进程用相同输入交替测量旧包和新包；最后七篇60页的完整输出和92图片对照。旧冻结参考保持不变，small_ocr两处旧置信度差异继续显式记录。

构建及受影响验证日志：`build/detection-table-build-20261029.txt`、`build/detection-table-{pixels,ocr-plan,materialization,text,host}-test.txt`。
