# V2/V3 版面模型压缩与速度实验

## 结论

分别生成并测试了全量 FP16 存储、仅矩阵权重 FP16 存储、仅卷积权重 FP16 存储、FP32 固定 batch=1、FP32 标准注意力融合，共 10 个候选。

**尚未找到可以确认“保持解析效果且显著提速”的候选。默认模型、已安装包及 Rust 代码均未更换。**

- V2 可以作为压缩研究候选：全量存储压缩约减半，13 页的检测数量、类别和阅读顺序均相同，但浮点框和分数有变化，不能承诺所有文档精度不变。
- V3 全量 FP16 存储在一页产生少一个检测结果，且多页多边形改变，按本次保持解析效果的要求不采用。
- 两者 FP32 固定 batch 或注意力融合，在已测页面保留类别、数量、顺序和多边形，但没有显示明显速度收益；不以这些少量测试宣称精度或性能完全相同。

## 方法与边界

从此前 7 份真实 PDF 中取首页、末页，单页文件不重复，形成 13 个独立页面。包含论文、报告、财报、密集表格、扫描页面等现有示例；没有加入文档专用规则。

所有候选共用冻结的真实输入：144 DPI RGB 渲染，800×800 三次插值、FP32/255、NCHW，保留实际页面 scale_factor。没有改变输入分辨率、检测阈值、类别集合、候选数、NMS 或阅读顺序算法。

ORT 1.26.0 CPU、自动线程、arena、ALL 图优化，关闭 profiling。各候选在独立进程中串行执行，相同首页预热；计时只包含 `session.run`，不包括加载、输入读取、NPZ 保存或后处理。保存全部原始输出及现有 Python PPDocLayout 的完整后处理结果，以默认阈值 0.5、auto 形状模式对照。

以下速度为**每个候选与原版的一次串行对照**，没有运行稳定 ABBA 性能基准。几百分点的差异不足以证明稳定收益；未将不同模型间的时间用于宣称其部署速度倍数。为避免对无明显收益或结果变化的候选追加大量回归，本轮没有做实际整份 PDF 替换回归或全量构建。

不存在带标注准确率评估，下面的“一致页数”是与原模型输出相比较，**不是识别准确率**。

| --- | ---: | ---: | ---: | ---: |
| 全量 FP16 存储、FP32 计算 | 62.17 | 7.602 秒 | 12/13 | 8/13 |
| 仅 MatMul 权重 FP16 存储 | 110.01 | 6.815 秒 | 13/13 | 10/13 |

全量或卷积权重压缩都在输入 `002` 上将后处理检测数从 16 变为 15；不是只改变小数位，不能直接接入。仅矩阵权重压缩避免了该页的数量变化，但仍有 3 页多边形不一致。

### 少一个区域的具体原因

进一步核查输入 `002`，对应 `demo/pdfs/demo1.pdf` 第 1 页。原版被保留的第 8 个阅读顺序区域为 `text`，坐标约 `[211.06,488.82,866.35,529.91]`（144 DPI 渲染像素），内容是作者单位，涉及 Cooperative Research Centre for Catchment Hydrology 和 University of Melbourne。

原版该区域分数为 `0.5042177439`；全量 FP16 存储候选中，同位置、同类别的框仍在原始输出里，分数变成 `0.4997572899`。新旧框 IoU 约 `0.99833`，位置基本不变，但新分数跌过现有 `0.5` 阈值，在阈值过滤时被删除。这不是模型完全未生成该区域，也不是仅根据输出总数推测出的原因。

FP16 存储会舍入原权重，恢复 FP32 计算也不能恢复已丢失的权重信息，因此临界分数可能跨过检测阈值。不能通过针对这页降低阈值来认定压缩无损；其他区域的误检与后处理行为也可能受影响。原模型及阈值继续保持不变。

固定 batch 和 FP32 融合分别有至多 0.000732、0.000488 像素的对齐坐标变化，主要是计算图变化后的浮点舍入差异。固定 batch=1 还限制了输入契约，不能替换仍需多页 batch 的通用模型。单轮约 3.82% 和 0.94% 的时间差不足以证明稳定提速。

## 图改写范围

- FP16 只改变存储，运行前恢复 FP32；17 个 V2 常量和 2 个 V3 常量超出 FP16 有限范围，保持原始 FP32。没有将大负数注意力常量截断或变为无穷。
- 部分存储压缩按 initializer 的所有消费算子选择，保留其他算子使用的权重。
- 两个模型各融合 7 组符合已核验模式的标准注意力为 ORT `MultiHeadAttention`，不改 FP32 权重，不处理 GridSample 或可变形注意力。
- 只移除确认全零的附加 attention bias，非零或动态掩码不匹配时不融合。保留原有缩放数值和输出投影。
- 权重完全相同的重复存储审计：V2 仅约 4.7 KiB，V3 无可用的大块副本；没有无损去重减半的空间。

没有尝试降低分辨率、删模型分支、提高阈值或减少检测数来获得速度；也没有继续扩大到 INT8，因为现有低精度存储已出现需要关注的结果差异。

## 工具、复现与结果

`scripts/migration/experiment_layout_compression.py` 提供：

```text
prepare --output build/<新的输入目录>
build --kind v2|v3 --output build/<新候选目录>
build --kind v2|v3 --half-ops MatMul|Conv --output build/<新候选目录>
build --kind v2|v3 --precision fp32 --batch-one --output build/<新候选目录>
worker --kind v2|v3 --model <模型路径> --inputs <输入目录> --output build/<新运行目录>
compare --baseline <原版运行目录> --candidate <候选运行目录> --output build/<新比较报告.json>
```

命令前加 `.venv/Scripts/python.exe scripts/migration/experiment_layout_compression.py`。目录和报告拒绝覆盖。

`scripts/migration/fuse_layout_attention.py --kind v2|v3 --output build/<新候选目录>` 生成独立 FP32 注意力融合候选。

汇总：`build/layout-compression-results-20261029.json`；真实输入和来源哈希：`build/layout-compression-pages-20261029/`；各候选的 `manifest.json` 保存源/候选路径、哈希、大小、改变范围，各运行目录保存原始 NPZ 输出、后处理 JSON、速度与内存报告及只读遥测。

V2 全量候选：`build/layout-v2-fp16-storage-r2-20261029/pp_doclayoutv2.fp16-storage.onnx`。这是供后续扩大样本验证的压缩候选，不是已验收默认模型。V3 全量候选同类路径仅保留为失败实验资产，不建议使用。

`tests/migration/test_layout_attention_fusion.py` 两项语义测试通过：动态 batch/不同 Q-K 长度下的融合数值比较，以及非零掩码不得误删。实际模型检查均通过 ONNX checker；脚本语法检查通过，原模型哈希未变。

当前 Rust 兼容层仍仅开放版面 V3，V2 不能仅改模型路径当成 V3 加载。本轮不扩大模型接入范围、不更换 SDK、不构建 Rust，未跑 CUDA。
