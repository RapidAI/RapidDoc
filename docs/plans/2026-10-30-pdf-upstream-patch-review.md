# DocVortex 0.6.8 PDF 补丁同步建议

状态：本表保留同步前审查结论。用户确认后的 #36 与前五项 PDF 补丁已实施，验证和已知失败见 [选择性同步交付记录](2026-10-30-docvortex-068-selected-pdf-delivery.md)。跨页表格与斜向水印仍单独审查。

## 结论

有必要选择性同步明确的解析缺陷修复，不能全目录覆盖，也不能因为12份101页通过就认为未覆盖场景的修复没有价值。当前 PDF 验收证明完成了既有 Python 基线迁移，不等于包含后来上游所有修复。

按实际来源提交核对，不能笼统说“上游提交一个都没有”：Python来源已经是标注0.5.16后的 `f5da4e6`（包含连字空格修复），Rust数值核另固定在 `2c1ec66`。以下表述针对尚未单独同步或需补齐的最新行为。

## 补丁优先级

| 提交/范围 | 同步前核对 | 审查建议 |
| --- | --- | --- |
| `8a3ff6c` 原生表格损坏文字拒绝 | 本地没有新增的 `_table_recovery/text_quality.py`。上游在输入/输出两阶段统计控制码、替代符和孤立代理项，达到条件时放弃原生表格候选 | 优先同步；拒绝候选后保留现有模型/OCR后备路径，不能把它接成整篇报错或直接丢表 |
| `72656be` 稀疏层级参数表 | 本地没有新增 `hierarchical.py`；不是原来所有稀疏表格能力都缺失，而是这个新候选与仲裁路径未同步 | 值得补入；必须与本地网格证明、图表仲裁和候选替换规则合并验证，保留负例 |
| `2c6c0ad` 旋转表头 | 上游为层级表格贯通字形旋转、物理占格与阅读/上下标方向。包含 contracts、candidate、text、table_pending 和表格样式改动 | 与层级参数表作为一组核对和同步，不能只复制渲染函数；不扩大为增强阅读顺序项目 |
| `d878cba` 上下标证据冲突 | 当前 Python inline matching/materialize 仍等于记录的旧来源，上游已有变化；Rust有既有上下标实现，不能按名称认定已经覆盖新行为 | 值得补入，并以原上游冲突样例验证；不是重写公式模型 |
| `a4c8b2e` 完整私用区 | 本地部分路径已有三段PUA识别，例如 Rust source_lines；但 vendor text_content 仍是单区间接口 | 补齐并统一所有相关路径，不重复改已经支持的路径，不把所有私用符号直接删除 |
| `ac4e28c` 跨页表格列网格与占格 | RapidDoc有自己的跨页表格流程和本地修复，上游改的是其 content/table 层 | 先按具体案例对照；按缺失行为选择移入，不整体替换RapidDoc表格合并器 |
| `72c1151` 有充分证据的斜向水印行过滤 | 涉及原生文字、局部方向、数学符号与表格投影 | 后续专项核对，必须验证旋转正文、斜体/公式及真实表头不被误删 |
| PDFium Windows字体ABI兼容等 | RapidDoc已有自己的绑定及共存机制，不能照抄Python CDLL适配作为Rust修复 | 只对实际调用路径做等价行为检查；不为追版本更换已验证的PDFium机制 |
| `be20158` 删除DocVortex本地OCR/模型下载、0.6强制原生后端及依赖调整 | 属于上游产品和后端边界调整，RapidDoc仍需要OCR/版面/公式/表格模型链路 | 不作为RapidDoc的功能补丁套入，不删除扫描件支持，不随这些提交升级运行库 |

这里的“表格文字质量门槛”是选择原生候选还是后备识别的规则，与此前移除的人工字符数量/资源容量上限不同。同步时不新增文档字符数或页数限制，也不吞掉真实异常。

## 建议组织

单独安排一轮有限的 PDF 缺陷同步：先建立上游各修复的实际参考和负例，再补齐 Python 参考及共享 Rust 对应路径，保持两边目标一致。开发时只跑受影响样例，阶段末复跑既有完整PDF基线，并单独记录新增用例的预期行为变化。现有本地PDF版面、表格/图形仲裁和原始图资产规则继续保留。

这与Office迁移解耦；不要求先重新追随全部DocVortex后端重构。性能原生化和通用架构调整不与本轮缺陷同步混做。

依据：本机DocVortex提交 `2de5f42b1884495313d9df63868e6a2f3d85fea0`、`git show`逐补丁检查、RapidDoc当前Python/Rust源码及 `build/docvortex-068-analysis/source-overlap.json`。上述优先级最初基于实现审查；后续测试、安装验收及一项已复现的既有宿主失败均在交付记录中单独列出，不能宣称覆盖全部文档。
