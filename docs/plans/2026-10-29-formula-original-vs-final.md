## 方法及校验

公式：相同 ORT 1.26.0 CPU、自动线程、arena 和 ALL 图优化；各轮独立进程、串行 A/B/B/A，固定 74 个真实 FP32 输入，相同短例预热，关闭 profiling。计时不含加载、输入读取、预热、结果检查。四轮依次为 40.701、30.372、29.437、34.865 秒，全部原始 token 与原 FP32 参考一致。

PDF：使用 `.venv` 已安装的 Rust 包，仅通过 `formula_config.model_dir_or_path` 切换公式模型路径，其余配置相同。先在一个进程依次解析原模型下的两份文件，再用另一个进程依次解析候选模型下相同文件。计时含首次模型加载、相同导出和 JSON 回读。

| PDF | 原模型 | 保留候选 |
| --- | ---: | ---: |
| demo1.pdf，13 页 | 42.675 秒 | 38.330 秒 |
| 03.pdf，10 页 | 55.029 秒 | 51.117 秒 |

23 页通过既有参考校验：Markdown、middle JSON、content list 相同，57 张图片的模式、尺寸和像素哈希相同；另直接比较两次实际输出的 Markdown 字节与解析后的 JSON。

运行仍有波动；四轮公式对照与单组 PDF 对照不构成所有文档和硬件的稳定提速保证。已测结果一致也不等于所有输入均不会因 FP16 存储或融合而发生数值差异。**没有实现数倍加速，主要成果为体积减半及一定的 CPU 提速。**

默认模型与已安装包没有修改，只有显式指定保留候选路径时才使用这些优化。
