## 改动

新增离线工具 `scripts/migration/fuse_formula_attention.py`，以哈希固定的投影外提 FP32 图为输入，保留原始线性投影、已缩放 Q、K/V 缓存、加性掩码、词表和终止规则。把 6 组自注意力与 6 组交叉注意力的 reshape/transpose/MatMul/Softmax/MatMul 链替换为本机 ORT 支持的 `com.microsoft::MultiHeadAttention`。

融合算子设置 `scale=1.0`，避免对原图已经缩放的 Q 再次缩放。传入原有四维 K/V 缓存以及原有浮点加性掩码。删除失去用途的节点时追踪子图对外层值的隐式引用，避免误删 Loop/If 使用的外层值。

清理后循环体从 963 个节点降至 468 个，节点数包含原图仍需保留的别名和控制流节点，不等于每一步实际算子调用数。保留 FP16 存储方式，候选文件约 284.07 MiB。没有新增运行时 Python 编排、Rust 自定义算子或模型下载依赖；使用现有 ORT CPU 内核。

生成路径：`build/formula-mha-half-20261029/formula-attention.onnx`。默认模型、安装包与原始权重文件未改。

## 冻结公式验证

FP32 融合图先通过 74 个真实公式原始 token 校验。随后将 FP16 存储融合候选与上一轮保留的 FP16 存储候选做关闭 profiling 的串行 ABBA 对照，各轮独立进程，同样的 CPU、自动线程、arena、完整图优化、短例预热，所有 74 个结果均与原始 FP32 参考完全一致。

| 顺序 | 模型 | 74 个公式推理耗时 |
| --- | --- | ---: |
| A1 | 上一轮 FP16 存储候选 | 39.046 秒 |
| B1 | 新融合候选 | 29.978 秒 |
| B2 | 新融合候选 | 30.669 秒 |
| A2 | 上一轮 FP16 存储候选 | 32.808 秒 |

均值 35.927→30.323 秒，耗时减少约 **15.6%**，速度比约 **1.185 倍**。这次比较是相对上一轮已压缩并外提投影的模型，不是相对最初原模型；不能将不同时间段的百分比相乘以宣称累计提速。

进程 CPU 时间均值 463.305→407.078 秒。峰值 working set 均值 1192.5→1189.6 MiB，结束时 private commit 1698.0→1689.9 MiB。本次新增融合的内存差异较小。

动态 batch=2 两组也通过完整输出数组校验：常规组合和短长混合，输出形状分别为 `[2,53]`、`[2,151]`。

结果仍有系统波动，不承诺每轮相同幅度。FP16 存储及融合可能改变浮点中间值，已测 token 一致不等于所有输入都数学逐位一致。

## 实际 Rust PDF 对照

通过 `.venv` 已安装包加载两个模型，先以旧候选顺序解析 `demo1.pdf`、`03.pdf`，再在独立进程以新融合候选解析相同文件；其余配置、导出范围和模型加载复用方式一致。

| 文档 | 旧候选全流程 | 融合候选全流程 | 旧公式阶段 | 融合公式阶段 |
| --- | ---: | ---: | ---: | ---: |
| demo1.pdf，13 页、56 个公式 | 39.967 秒 | 38.095 秒 | 22.262 秒 | 20.672 秒 |
| 03.pdf，10 页、74 个公式 | 60.687 秒 | 51.184 秒 | 40.433 秒 | 31.319 秒 |
| 合计 | 100.654 秒 | 89.279 秒 | 62.695 秒 | 51.991 秒 |

两个文档合计全流程耗时减少约 **11.3%**；公式阶段合计减少约 **17.1%**。这是一组串行实际流程对照，包含首次模型加载、相同导出和 JSON 回读，不是稳定性能保证。未观察到数倍提速。

23 页全部通过既有参考校验：Markdown、middle JSON、content list 一致，57 张图片的模式、尺寸、像素哈希一致；另直接比较了两次实际输出的 Markdown 字节和解析后 JSON。运行中未报错。原始模型、上轮候选和融合候选的 SHA256 验证通过，未替换默认路径。

结果位于 `build/formula-mha-comparison-20261029/pdf-comparison.json`，实际导出位于 `build/formula-mha-pdf-{baseline,candidate}-20261029/`。
