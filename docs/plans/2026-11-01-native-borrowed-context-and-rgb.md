# 原生 PDF 所有权、借用上下文和 RGB 渲染优化

接续 [JSON 传递优化](2026-11-01-native-value-transfer.md)。新版函数栈采样中，Value serializer 的主线程样本占比约 23.7%，JSON 子树 clone 约 24.2%（分类重叠，不相加）。后续改造针对仍存在的真实复制与渲染转换，不调整识别规则。

## 改动

- 图形分类、Form 选择、目录行提取、文字噪声清理和栅格图表分组新增内部所有权入口。页面已拥有的 source/lines 直接移交，保留公开诊断接口。Form 选择只生成实际改变的两个别名映射，避免再复制完整字符树。
- 表格提交直接更新页事务自身的 source。公开诊断接口仍操作独立副本并返回原字段；内部消除 source 大树的请求包装和结果往返复制。候选生成、排序、仲裁和恢复逻辑未删减。
- 行内上下标准备在生产兼容作用域借用整页 tight/origin 映射，仅构造本行旋转后的数据。不再为每行复制整页映射。公开 JSON 接口、有限预算路径及输入错误保持原校验；内核角色判定、顺序、阈值和数字精度保持。
- RGB 渲染直接整理 PDFium 已经反转通道顺序的 RGB 缓冲，原地移除行尾 padding。消除 RGB→RGBA→RGB 的扩展与逐像素回写；格式、渲染参数、抗锯齿、RGBA 路径和 PNG 编码器保持。

## 验证

- 16/65/129 页公开原生规则输出完整快照与上一安装版本严格一致，包括数字类型、全部未知字段、数组顺序及资产身份。密集长表格一页完整快照一致。
- 默认模型下扫描、论文、印章 6 组公开选页/单页窗口对照通过；未跑全部语料。
- 30 组 RGB、RGBA、模型渲染对照覆盖四个旋转方向、奇偶宽度、行对齐、长边上限及本地真实 PDF。尺寸、scale、图像模式、全部像素和 PNG SHA256 均严格一致。
- RGB 行整理单测覆盖 288 个宽高/padding 组合与无效长度/溢出；32 组借用上下标场景检查四方向、compact 标记、坏映射和坐标越界的角色/错误一致性。
- 4 项借用入口相关 Rust 测试通过，含固定 Python 脚本四方向参考、真实图形源参考、边界预算和原生文档前缀；271 组固定 Python 文字/脚注/行簇/脚本参考通过；安装资源策略 5 项通过。

## 测量与交付方法

首轮 `build/borrowed-native-after-20261101.json` 与编译重叠，首次计时明显受干扰，**不作为性能验收依据**。最终测试在编译与回归全部结束后，通过 `compare_native_pdf_wheels.py` 顺序安装上一版、新版，再测试 Python；各自独立进程连续两次调用。相同 129 页输入、原生规则、关闭公式/表格模型、txt 和 64 页窗口；两边保留相同轻量阶段诊断，没有 cProfile 或堆栈采样。

最终安装候选为 `build/borrowed-native-r2-20261101/rapid_doc_rust-0.1.0-cp310-abi3-win_amd64.whl`。比较脚本结束时保留候选包在项目 `.venv`。原始顺序测量位于 `build/borrowed-native-r2-comparison-20261101`；回归位于 `build/borrowed-native-r2-{window-verify,public,dense-verify}-20261101`。

复核脚本 `scripts/migration/report_borrowed_native_delivery.py` 校验已有输出和 wheel/安装指纹，生成 `build/borrowed-native-delivery-receipt-20261101.json`，不重新解析。

本轮不涉及 Office 或 CUDA，没有新增峰值内存结论。顺序比较每版只有两次调用，不是交替多轮基准；原生规则收益不能外推模型主导的扫描件。即使速度明显改善，也必须依据实测报告与 Python 的剩余差距。

## 最终结果

构建和回归结束后的独立进程顺序对比：

| 调用 | 上版 Rust 秒 | 新版 Rust 秒 | 耗时下降 | 同期 Python 秒 |
| --- | ---: | ---: | ---: | ---: |
| 首次 | 31.006 | 18.895 | 39.1% | 11.894 |
| 复用 | 31.063 | 18.787 | 39.5% | 10.318 |

热调用阶段：原生分析 19.898→13.660 秒，渲染 7.546→1.513 秒，组装 2.730→2.719 秒。两个版本和 Python 的全文 Markdown SHA256 一致。完整结构与资产比对在独立回归进程进行，不放进性能计时。

这份工作负载有明显端到端收益，但新 Rust 热调用仍为同期 Python 的约 1.82 倍，尚未追平。剩余主要成本仍在原生分析及组装，不能因渲染加速就宣称模型推理或全部 PDF 已同幅改善。首轮受编译干扰的 47.4/28.3 秒没有参与结果计算。

候选 wheel 已保留在项目 `.venv`，安装二进制 SHA256 `bfbde1f483393dc413d85f74e8d3e26e96070a2bedf42af33e7bbf557dc317de`，与 wheel 和公开回归 manifest 一致。收据复核成功；现有 demo 直接使用该环境运行即可，无需手动改参数或重新构建。
