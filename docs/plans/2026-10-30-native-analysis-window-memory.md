# 原生分析遵守 PDF 批次生命周期

用户目标：修复 Rust 原生模式绕过 `pdf_pages_batch=64` 的全文预分析；不通过限制文档大小或降低识别精度控制内存。

修改：把 `predict_range` 放进既有 window 循环，只处理当前 `[first,last)`；按批构建相同文档统计，失败时仅本批回退模型。使用 `Value::take` 交接页面数组，去掉两处深拷贝；完成当前批布局后释放原生结果。原有批内 OCR/公式/表格次序、最终段落及跨页表格合并不变。Python 参考原本就是先截取当前批 PDF 再分析，不改其算法。

验证：先以无模型合成多批文档核对范围、索引、进度顺序和错误传播，再对 328 页源文档以默认 64 页、正式 RapidDoc 入口串行运行 Python/Rust，记录峰值与各批内存。保存完整输出差分；已有小文档回归只在阶段末执行。旧诊断 `analyze_native_pdf` 显式全文语义不冒充生产分批入口；此前内存失败作为比较背景，不能视为同条件 Python 基准。


已定位并处理的额外占用：
- `collect_range` 的图片区域分类只读取行的 text/bbox/angle/effective_height/dominant_font_weight，不再复制行内所有字符几何；整批图片分类输入用完即释放。
- 几何、边缘角色和文档阶段增加所有权交接，原数组通过 `Value::take` 传递；逐页消耗原始页面，及时丢弃已被后续结果替代的快照。
- 正式原生路径仍调用相同几何、表格、正文、标题、引用、行内样式算法；只不保留供诊断返回的完整检查点。行内物化仅传递该函数实际消费的脚本、样式、链接、页面尺寸和间距证据。
- 输出预算无限制时不再构造整篇 JSON 字符串来检测大小；有限预算采用相同 serde 编码的流式字节计数，并验证边界、转义及 Unicode 行为。

首轮仅移动批次仍不足：正式入口首个 64 页原生分析的观察峰值达到 13,315,756,032 字节后终止，未计为通过。上面额外修改后，首个完整批次完成，工作集回落至 835,289,088 字节，系统记录峰值 4,901,699,584 字节；完整 328 页验证仍在运行，结果以最终 receipt 为准。

相同配置 Python 基准已完成 328 页：默认64页、原生规则版面、txt、开启表格/OCR后备，关闭公式模型和印章；采样峰值工作集 2,987,880,448 字节，系统峰值 3,042,643,968 字节。两引擎串行运行，未据此宣称所有配置都只占固定内存。
