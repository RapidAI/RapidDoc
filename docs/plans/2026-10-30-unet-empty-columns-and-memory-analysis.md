# UNET 空列区间兼容与内存差距

## 根因与修复

连续选择目录文档源第289–290页即可复现，单独第290页不触发；不依赖整篇328页重跑。捕获到17个UNET格框，末行全宽格已消耗3列，后续重叠小格得到列起点3。Python `TableRecover` 返回 `[7,7,3,2]`，该列区间为空，渲染循环不会填入网格；Rust原先在跨度计算前直接返回“UNET 合并格起点越界”。

原模型表格入口改用 `recover_legacy`，保留与Python相同的逻辑坐标和源格索引、OCR匹配及候选比较。旧版渲染按Python的空区间和 `max(span,1)` 几何估算规则处理。未裁剪到最后一列、重排格子、清空整表或跳过模型。严格恢复/渲染接口仍拒绝该区间，保留其独立合同；其他非法几何、非有限数等校验不变。

持久参考 `tests/fixtures/upstream_068/unet_empty_columns.json` 保存真实格框、平移副本和去除重叠的对照，由Python原实现生成逻辑坐标与完整HTML。生成脚本 `scripts/migration/export_unet_empty_columns.py`。

## 为什么Rust仍可能比Python占用更多

此前整篇原生预分析不遵守64页窗口、保留诊断快照的问题已经修复，详见 `2026-10-30-native-analysis-window-memory.md`。仍存在以下实现差异，不能只按语言推断实际峰值：

- Rust兼容流水线使用通用 `serde_json::Value` 对象树。原始字符、行内字符、几何映射和后续页面结构经常各有一份；复制JSON子树会复制字符串、数组和对象节点。Python若复用字符对象引用，不会产生同等深拷贝。本次确认几何规划只读 `Page.lines`，因此改为借用输入切片，消除整批行及其字符的一次深拷贝；处理顺序和所有几何值保持不变。此外，原生收集和最终模型输出封装均改为移动已有JSON页面数组，避免 `json!` 序列化借用值而重建整批对象树。
- 同一窗口还会保留页面事实、渲染图片、模型输入及中间结果；最终正文和图片资产随已完成页数累计。窗口限制的是当前分析范围，不是整篇结果的固定内存上限。
- PDFium读取字符、Form等函数目前多次从原PDF字节打开文档。Python先切出批次PDF再分析；Rust当前主要限制页码范围。这是下一轮统一文档句柄/批次输入复用的明确检查点，尚未定量归因，也不能随意换切片器，以免改变Form和旋转几何。
- 进程峰值还包括PDFium、ONNX Runtime及分配器缓存，并非最终输出文件大小，也不能据批次后工作集回落就推断所有分配都会立即返还操作系统。

进一步定位到页边角色阶段：内部 `Page` 原先同时深拷贝完整source及其lines，检测分隔线前又用 `json!` 重建一次整批sources。现内部source改为不可变借用，仍独立保存需要修改语义标签的lines；只读分隔线阶段直接读取现有source切片，不再构造整批请求副本。输出source仍按原合同独立生成，不改变调用方输入。`native_marginals_owned.json.gz` 保存修改前安装包生成的1/2/3页完整前缀参考，检查所有字段而非只检查正文。

有继续降低内存的空间，但尚不能保证低于Python；需要以相同页段、模型、默认64页窗口、串行独立进程实测。不能以关闭表格/OCR、缩小默认批次或减少识别内容证明更省内存。

## 最终实测与交付

继续移除页边角色/分隔线阶段的整批副本后，64页解析成功：系统记录峰值 **3,889,098,752字节（3.62GiB）**，相对修改前4.56GiB下降 **20.6%**。采样峰值工作集3.55GiB，采样峰值私有提交3.83GiB（修改前4.68GiB）；采样可能遗漏短暂峰值，因此主结论使用操作系统记录峰值。Python同配置系统峰值2.26GiB，当前Rust仍约为其1.61倍，尚未达到比Python省内存。

最终340.40秒，未验证到整体提速，不作速度提升结论。三轮Rust与Python均串行独立进程，保留默认64页、相同选择和模型配置，但未控制用户其他程序的内存/CPU负载；不能将单次耗时微小波动视为算法收益。

与修改前Rust相比，最终64页Markdown、content_list、middle_json及45个图片资产的名称、像素、编码全部一致；旧包1/2/3页原生阶段参考全部一致。之前记录的Python/Rust表格截图差异仍在，未隐藏或针对该页补丁。

最终wheel：`build/unet-memory-borrowed-wheels/rapid_doc_rust-0.1.0-cp310-abi3-win_amd64.whl`，已安装项目原 `.venv`，148个包文件逐字节匹配。UNET两页复现、132组原生PDF参考、14组合并/所有权参考、分批生命周期测试均通过。完整收据：`build/unet-memory-analysis-receipt.json`。
