# 原生表格候选与字符的分配开销

后续状态：用户整篇严重回退，2026-10-29 10:56 已撤回该安装包并恢复 09:31 对应 wheel。以下保留为实验记录，不能继续视作当前交付状态；见 [回退记录](2026-10-29-performance-regression-rollback.md)。

输入证据：固定密集表格语料 20,198 个原字符、6,732 个字形、847 个单元格，渲染请求约 14 MB。原候选仲裁重复深拷贝数组；候选类型转换先克隆 JSON 再反序列化；单元格准备为了判断 8 MB 字节预算对每个选中字形/字符创建完整临时 JSON String。

实现范围：

- 仲裁仍收到相同 JSON 根对象、数组、配置和顺序，仍经过原树校验及原仲裁。用临时所有权转移替代克隆，Drop 在返回、错误和 unwind 时恢复原数组。原 Work 收费时点与数量不变。
- 候选生成结果的数组直接移出已经拥有的 JSON，不再克隆；只判断是否有足够列时，完整遍历原候选列值但不复制候选。完整遍历保留，不通过短路改变内部非法值访问顺序。
- 候选网格规格和文字结构直接从借用 Value 反序列化；保留原字段、类型检查和后续字形/预算校验。
- 字节预算仍由同一 serde_json 紧凑序列化器逐字节计算，包括 Unicode、转义及数字表示，只把输出改为计数 Writer，不创建临时字符串，不改 8 MB 门槛与累加顺序。

没有修改表格判定、候选优先级、阈值、文字落格、模型、方向或阅读顺序。既有 `build/migration/*.json` 不改写。只跑受影响测试与表格文档，不跑全量或 CUDA。
