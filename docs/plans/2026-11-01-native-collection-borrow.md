# 原生 PDF 数据收集的借用输入与数组移交

基线为 `native-finish-borrow-20261101`。本轮针对原生事实读取之后的 Rust 数据转换；未改模型、算法、阈值、数值精度或 Python 生产解析。

## 实现

- 原生字符建行、间距准备、样式/链接证据和字重分组接收借用字段，不再为只读调用构造带完整字符树的临时 JSON。公开接口委托给同一处理实现，字段/数组验证顺序保持。
- 字符建行的已有字符数组、合并后行数组直接返回 Value，不再对已有 Value 重新序列化；字重修正复用已复制行里的字符数组，避免再复制一次。字重检测依然按原选择规则决定是否渲染和采样，没有跳过像素判断。
- 收集结果中的 drawing_lines、path_infos、Form 数据、样式/链接结果直接移交；tight/loose/origin 映射取出后按原始数字索引排序，再移交坐标，不复制后遗弃原映射。
- 字符建行在显式有限树预算下回到完整请求验证，保留原树资源计数。其他内部接口原先未做入口树验证，继续保留原字段/Work 检查；公开入口仍做完整树验证。

## 针对性参考

`scripts/migration/export_native_collection_reference.py` 仅生成原 Python 的相关参考，不读取历史 build/migration JSON。固定文件 `tests/fixtures/native_collection_reference.json.gz` 保存来源 SHA 和所需 PNG 字节，自包含，不依赖生成时 PNG 路径。

- 16 组真实字符建行：既有实际 PDF 字符、四种页面旋转。
- 48 组间距准备：无指定/空指定/指定字符边界。
- 218 组样式与链接证据：原 Python 合成/随机场景，生成器在历史真实页面输入之前截断。
- 108 组像素字重识别，包括 9 个真实采样得到的加粗正例、方向/字体/几何覆盖/不渲染等原场景。

两类作用域下比较原包装入口与借用入口的输出/Work，并对照原 Python；额外检查缺失/null/错误字符/错误绘图和注解输入。加上既有 6 项自有行、分式、图内文字及完整页收尾参考，本轮 8 项受影响 Rust 测试通过。记录 `build/native-collect-borrow-focused-20261101.log`。

## PDFium 复用边界

已确认多个事实读取器各自加载文档/页面。现有全局运行库锁只允许在调用内操作原生句柄，签名读取还会创建 Form 环境。共享句柄需要单独验证关闭顺序、错误/异常清理、Form 副作用和线程隔离，不能直接添加全局缓存。本轮没有修改 PDFium 句柄生命周期，收益不能归为复用文档。
